# Native identity settings and authorship

## User behavior

Settings → Identity (`/settings/p6rIdentity`) reports the provider-resolved person
for the current connection, or an explicit unconfigured/unauthenticated/unavailable
state. It offers a refresh, collapsible issuer/subject details, and a link to the
shared Appearance settings. It does not offer claimed identity editing or personal
theme overrides.

New native messages show the verified author snapshot above their bubble and
carry sender context to the model. Existing unattributed history stays unknown.
Mentions remain recipients; they do not establish authorship.

## Upstream maintenance

Patch 0016 keeps provider admission, context formatting, and author display in
P6R modules/components. Upstream touchpoints are route-definition registration,
optional metadata forwarding through existing create/send/fork/edit/retry and
queue paths, and the existing event-to-timeline projection. It does not copy the
upstream dispatcher or replace command parsing. `/compact` keeps its original
structured input. The existing host-daemon command schema accepts the enriched
ordinary prompt; no wire field is added.

One nullable queue column is necessary to survive deferred dispatch and restart
without resolving a different sender. Its migration snapshot is generated by
Drizzle; most patch lines are that snapshot and regression tests. Grouped first
starts now forward the existing optional inputGroups field, preserving each
accepted sender. Retry reads original event metadata. The optimized queue path
defers attributed rows to the existing general dispatcher, avoiding a second
identity implementation in the fast path.

Provider rejection or outage fails closed on configured native write routes.
Live validity is checked before acceptance; accepted queue snapshots can drain
after that request ends. Client-supplied author metadata is not an authority.

## Checks and limits

- Actual Hono routes + loaded controlled provider: create/live send, grouped
  queues, scheduled first dispatch, retry, denied/retired provider, and compact.
- Existing queue, failed-retry, recovery, native acceptance, mention and daemon
  ingress regressions; database migration rewind tests; SDK/CLI command test.
- Timeline per-group author projection, unchanged historical text, settings
  states, and hiding previous identity while rechecking.
- Scoped Turbo typechecks/builds and full overlay replay/namespace verification.
- Browser smoke uses the built preview; automated ready-state UI fixtures are
  not evidence of a real Tailnet user's admission. The human's own browser check
  is the live identity witness. Historical unknown sends are not backfilled.

The change does not introduce per-person theme storage, notification delivery,
new provider credentials, or an upstream protocol replacement.
